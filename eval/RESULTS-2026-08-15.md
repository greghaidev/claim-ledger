# Fact-Check Gate — 2026-08-15 seat refresh (short eval)

The first re-seat cost $12.58 and the operator's instruction for this one was explicit: a $3
eval, a swap, and a recorded decision, rather than an exhaustive process. This run used the new
`--battery quick` (4 variants) under a hard `--max-spend 3.00`.

**The headline is not a seat.** It is that the roster's cost model was measuring a price this
account cannot obtain — so the affordability filter, the single biggest lever in the design, was
ranking candidates on rates nobody was ever billed. Correcting it moved two verdicts and made
the re-seat in §5 possible.

The seat changes follow from that: **light $0.131 -> $0.010 a round, heavy $0.496 -> $0.201**,
with no measured quality loss. Prompt caching adds up to 36x on repeat rounds — though §4
shows why the anchor deliberately declines it.

---

## 1. The cost model was wrong, and nothing failed to tell us

`or_peer.PRICES` had the anchor seat `deepseek/deepseek-v4-pro` at **$0.435 / $0.87** per 1M
tokens, unchanged since the day it was seated. The live catalog on 2026-08-15 says
**$1.168 / $2.336** — 2.7x. `check_prices.py` (which is a manual step, not a CI gate)
found it immediately; nothing else did, because the gate computes its printed cost floor from
the same stale table it was budgeting against.

That alone pushed the seated anchor to **$0.203 per 150K-token round, over the $0.20
affordability ceiling it was seated under.** The existing test suite proved it mechanically:
`test_anchor_seat_is_affordable` went red on the price refresh, before any judgement was
applied.

### But the reprice was not really a reprice — it was routing

`deepseek/deepseek-v4-pro` is served by **18 different endpoints**, spanning:

| | cheapest | dearest | spread |
|---|---|---|---|
| input $/1M | 0.348 (StreamLake, GMICloud) | 1.910 (Azure) | **5.5x** |
| cache read $/1M | 0.0036 (DeepSeek) | 0.330 (Venice) | **91x** |

The catalog's headline price is the cheapest endpoint of the moment. **The slug does not
determine what you pay — the routing does**, and OpenRouter's headline moving from one endpoint
to another looks exactly like a vendor reprice from inside our tooling.

Two changes follow, both mechanical:

- `record_dispatch` now logs **which provider actually served** each dispatch. Without it a
  routing change and a price change are indistinguishable in the ledger — which is how this was
  misread on first look.
- `score` now reports a **measured / table price ratio** from the eval's own billed dispatches,
  and `seat` ranks rosters on the corrected number. The affordability filter — the single
  largest cost lever in the whole design — was ranking candidates on a rate we do not get.

## 2. The caching lever: real, and it needed two fixes

DeepSeek prices cache reads at **$0.003625/M against $0.435/M cold — 120x** on
`deepseek-v4-pro-0813`, and its endpoint reports `supports_implicit_caching: true`. The gate's
payload is input-dominated and its *sources* do not change between iteration rounds, so almost
the entire input half of every round after the first is cacheable.

**It was structurally impossible to hit that cache before today.** A prompt cache keys on an
exact prefix, and `build_user_prompt` put the FINAL ARTIFACT — the one part that changes when
you edit and re-run — *first*. The shared prefix between two rounds was the empty string.

Fixed: sources first, artifact last, with the system prompt updated to describe the order it
actually sends. Guarded by `the cache tests`, which asserts the
ordering property (and its converse, so it cannot pass vacuously) rather than the discount.

### The second blocker was routing churn, and it is fixed — no setting required

Reordering alone changed nothing. Measured with `the prompt-cache probe`:

```
model: deepseek/deepseek-v4-pro-0813   (unpinned)
round 1 (cold)   -> GMICloud    21,804 tok        0 cached   $0.02704
round 2 (edited) -> Novita      21,810 tok        0 cached   $0.02958
```

**Zero cache hits, because consecutive requests landed on different backends** — GMICloud then
Novita — and a prompt cache is per-provider. OpenRouter's default routing moves between
endpoints request to request, so a payload can never reuse its own prefix.

Pinning one endpoint fixes it completely:

```
model: deepseek/deepseek-v4-pro   pinned gmicloud/fp8
round 1  -> GMICloud   21,804 tok   21,760 cached   $0.00074
round 2  -> GMICloud   21,810 tok   21,760 cached   $0.00079
```

**$0.02699 -> $0.00074 on the same payload — 36x.** Shipped as `claim_ledger.PROVIDER_PREFS`,
pinning the anchor to the three cheapest endpoints that price cache reads, **with
`allow_fallbacks` left TRUE**: the gate is fail-closed, so disabling fallback would convert an
unavailable endpoint into a FAIL on an artifact nobody reviewed. Losing the cache is an
acceptable failure; losing the verdict is not.

### A correction, and a judgement call that is deliberately NOT taken

An earlier draft of this document reported DeepSeek's own endpoint as unreachable and asked the
operator to check an account setting, naming the wrong page and the wrong cause. The precise
error only appears under `provider: {"only": [...]}`; `order` + `allow_fallbacks: false`
returns a generic "No endpoints found". The real message is:

> No endpoints available matching your **guardrail restrictions and data policy**.
> Configure: https://openrouter.ai/settings/privacy

So the endpoint is filtered by this account's privacy guardrail, which excludes providers that
may train on inputs. DeepSeek first-party is genuinely cheaper — **$0.435/M in and $0.003625/M
cache reads, 8x below GMICloud's cache rate**.

**Not recommended.** Unblocking it would send investor artifacts and primary business data to a
provider that trains on them, and the pinned-reseller route already captures most of the
saving. This is recorded as a decision rather than left as an open operator ask.

## 3. Process changes shipped with this run

| change | why |
|---|---|
| `--battery quick` is the default (4 of 9 variants) | recall and coverage **saturated** in the last eval — 5 variants separated nobody |
| `--max-spend 3.00`, enforced between dispatches | a ceiling checked after the fact is a report, not a ceiling |
| trial-major job ordering | hitting the cap now costs trial *depth* uniformly instead of leaving late-sorted candidates at zero trials |
| submit-as-slots-free scheduling | seats differ >10x in latency; fixed waves idled five workers behind one straggler |
| `PARTIAL BATTERY` banner on `score` | "100% recall" over two defects must not read like "100% recall" over seven |
| `decide` → `DECISIONS.md` | the roster's reasoning lived in three places that drift; a cheap eval is only cheap if its answer survives |

**What the short battery gives up, plainly:** two defects is a recall *floor* — it catches a
seat that has stopped reading its sources; it cannot tell you which seat is sharpest on subtle
defects. Use `--battery full` for that question.

| `glm-5` | 100% | ok | 100% | 100% | 1.0 | 25.8 | 0.105 | 192 |
| `glm-5.2` | 100% | ok | 100% | 100% | 0.3 | 34.6 | 0.126 | **35** |

† at a non-quantized endpoint — see "RESOLVED: it was fp8 quantization" below. The 7.3 was an
artifact of routing, not the model.

**Quality did not discriminate, again.** Every candidate: 100% format, 100% leak refusal, 100%
recall on the quick battery, 100% figure coverage, zero bad citations. That is now a repeated
result across two evals and fourteen candidates — **the panel is not buying coverage, and no
future re-seat should be argued on coverage grounds.**

What separates seats is over-flagging a clean base, price, latency, and extraction breadth.

### The seated anchor appeared to fail the over-flag gate — it did not

`deepseek-v4-pro` flagged **7.3 claims per clean-base run** against 0.67 in the July eval — a
10x jump — and the harness excludes it, because OR-of-FAILs means such a seat can never return
PASS. Two changes could explain it, and they are both mine: the route pin (GMICloud serves
**fp8-quantized** weights) and the prompt reordering.

**The flags are not degraded output.** They are coherent, reproducible across all three trials,
and defensible — every one targets an unsupported *causal or rhetorical* assertion:

> "A yield buyer bidding on $200,000 houses is bidding against people who are not doing
> arithmetic" — *no supplied source establishes counterparty motivation*
>
> "Those parcels are uncontested because the rest of the market looked at them and passed" —
> *no buyer-behaviour data is supplied; only the uncontested share is sourced*

So this is a stricter *posture*, not a broken seat — and the strictness is arguably right for
investor copy. But it is fatal in an OR-of-FAILs panel, which is a fact about the aggregation
rule, not about the seat's judgement.

### The gate itself turned out to be noisier than the thing it was gating

Trying to attribute the 7.3 produced a more important finding. Six runs of `deepseek-v4-pro`
— **same model, same prompt, same GMICloud endpoint** — split into two clusters:

| arm | per-run flags | mean |
|---|---|---|
| route pinned | 7, 7, 8 | 7.3 |
| default routing (`QUALITY_TEAM_NO_PROVIDER_PIN=1`) | 4, 2, 4 | 3.3 |

The A/B could not isolate quantization, because **OpenRouter's default routing picks the
cheapest endpoint anyway — which IS GMICloud fp8.** Both arms landed on identical weights. The
difference between them is unexplained and n=3 per arm is too thin to call it.

What this does settle: **a hard gate was being applied to a mean over 3 runs of a quantity that
measures 2 to 8 on identical input.** `score` now records per-run counts and `seat` prints them
with every exclusion, plus a `STRADDLES THE THRESHOLD` warning. It paid for itself immediately:

```
excluded (OVER-FLAGS a clean base: 7.3/run > 2.0) — per-run [7, 7, 8], n=3: deepseek-v4-pro
excluded (OVER-FLAGS a clean base: 2.3/run > 2.0) — per-run [0, 1, 6], n=3: deepseek-v4-pro-0813
    STRADDLES THE THRESHOLD — this exclusion rests partly on variance.
```

`-0813` was being excluded on **one outlier run**. Nobody reading "2.3/run > 2.0" would have
guessed that. `deepseek-v4-pro`'s `[7, 7, 8]` is, by contrast, consistent and real.

### RESOLVED: it was fp8 quantization

A third arm — pinned to `digitalocean`, the cheapest **non-quantized** endpoint for this slug —
settled it:

| arm | quantization | per-run flags | mean |
|---|---|---|---|
| GMICloud, route pinned | **fp8** | 7, 7, 8 | 7.3 |
| GMICloud, default routing | **fp8** | 4, 2, 4 | 3.3 |
| DigitalOcean | **none** | 1, 0, 0 | **0.33** |

0.33 lands on July's 0.67 baseline. **fp8-quantized weights measurably degrade this seat's
judgement on a coverage-and-obedience task** — it is not the prompt reordering, and it is not
the model.

Three consequences, all acted on:

1. **The outgoing anchor is unseated on COST, not on quality.** At full precision
   `deepseek-v4-pro` is among the *cleanest* seats in the field. It still loses: ~$0.151/round
   at DigitalOcean rates against flash's ~$0.011, for the same 100% figure coverage. The
   earlier reading in this branch — "excluded on over-flagging, consistent and real" — was
   attributing to the model what belonged to the endpoint, and is corrected here and in
   `claim_ledger.py` rather than quietly dropped.
2. **Cheapest-endpoint pinning is a quality decision, not only a cost one.** The anchor now
   prefers `digitalocean` (non-quantized). `glm-5.2` and `minimax-m3` stay on fp8 with a stated
   basis: both were measured clean at fp8 here, and their non-quantized alternatives cost +46%
   and do-not-exist respectively.
3. **The anchor deliberately forfeits the cache**, measured both ways:

   ```
   digitalocean   (not quantized)  $0.00148 -> $0.00148   no cache hits
   streamlake/fp8 (quantized)      $0.00140 -> $0.00030   99% cached, 4.7x
   ```

   Under a cent a round at production size. **This qualifies the 36x headline: the caching win
   scales with price and payload.** It mattered enormously on a $0.131/round seat; on a
   $0.010/round seat it is noise, and quality wins.

## 5. The decision

| | before | after | change |
|---|---|---|---|
| light (anchor) | `deepseek-v4-pro` | **`deepseek-v4-flash`** | $0.131 -> **$0.010** /round |
| heavy panel | `deepseek-v4-pro` + `glm-5.2` + `qwen3.7-max` | **`deepseek-v4-flash` + `glm-5.2` + `minimax-m3`** | $0.496 -> **$0.201** /round |
| lineages | DeepSeek / Zhipu / Alibaba | DeepSeek / Zhipu / MiniMax | 3, unchanged |

**13x cheaper on the iteration class, 2.5x on the ship class, with no measured quality loss.**

**Both exits are cost decisions.** `deepseek-v4-pro`'s apparent over-flagging turned out to be
fp8 quantization at the endpoint it was routed to (§4); at full precision it is one of the
cleanest seats in the field, and it loses purely on ~$0.151/round against flash's ~$0.011.
`qwen3.7-max` is out at $0.239/round measured, above the $0.20 ceiling — and it was already over
when it was seated. The headline price hid it.

Recorded in [DECISIONS.md](DECISIONS.md) with the reversal condition.

### The observation that survived the correction

Those extra flags were an fp8 artifact, so the "stricter posture" reading of them is withdrawn.
What survives is narrower and still worth keeping: even at full precision the seat produced one
flag on the "clean" base, and the flags it produced under quantization were *coherent* — they
targeted unsupported **causal** claims ("those parcels are uncontested because the rest of the
market looked at them and passed"). Nothing in the bundle establishes that.

The fixture's base is clean by convention, not by proof. Whether the gate should block investor
copy on unsupported causal assertions remains a live question about the **artifact standard**,
but it is no longer supported by the evidence I first cited for it, and it is not a reason to
seat a 14x dearer model. Recorded as a question, not a finding.
